# Промпт створення публічного плагіна MajorDoMo «TabCalorie»

> [!NOTE]
> Робочий документ. Версія 1.2.0, 2026-11-20. Мова за замовчуванням — українська.
> Після уточнень розділ «Відкриті питання» оновлюється, і його рішення стають вимогами.

## 1. Мета та контекст

Створити **публічний** плагін (доповнення) для системи розумного будинку MajorDoMo,
який імпортує дані харчування з застосунку «Таблиця калорійності» (ТК, Dine4Fit,
`tablycjakalorijnosti.com.ua` / `kaloricketabulky.cz`) у локальну БД MajorDoMo
та надає інтерфейс контролю споживання вуглеводів і формування звітності.
Плагін має бути безпечним для публікації в
`https://github.com/mambursoft/majordomo_TabCalorie`.

**Не є метою**: медичні рекомендації, автоматичне дозування інсуліну, заміна щоденника ТК.

## 2. Обмеження середовища (перевірено в `majordomo-core`, коміт `32eb1413`)

- Модуль: `modules/tabcalorie/tabcalorie.class.php`, клас `tabcalorie extends module`,
  конструктор викликає `checkInstalled()`; реєстрація в `project_modules`, прапорець
  `cms/modules_installed/tabcalorie.installed`, рядок у таблиці `plugins`, іконка
  `img/modules/tabcalorie.png`.
- Конфіг модуля зберігається в `project_modules.DATA` (`serialize`) через
  `getConfig()/saveConfig()`; секрети не зберігати у відкритих шаблонах.
- Власні таблиці — через `dbInstall()` heredoc формату `table: FIELD type...`
  (дзеркало в `modules/tabcalorie/db_install.php`).
- Об'єкти/властивості/методи створюються програмно: `addClass()`, `addClassProperty()`,
  `addClassObject()`, `getObject()->setProperty()`; читання — `gg('Obj.Prop')`.
- Код методів БД зберігається **без `<?php`** (виконується через `eval()`).
- Сторінки: `templates/tabcalorie/*.html` (jTemplates: `<#LANG_*#>`, `[#begin#]`, `[#if#]`);
  адмінка — `admin(&$out)` + `action_admin.html`; публічна — `run()` + `tabcalorie.html`.
- Мови: `languages/tabcalorie_{default,en,uk,ru}.php` із `$dictionary` і
  `define('LANG_'.$k, $v)`; Uk — дефолт, En/Ru — повні переклади.
- Пакет для Market: `.tar.gz` зі структурою відносно ROOT MajorDoMo (`modules/`,
  `templates/`, `languages/`, `scripts/`, `img/`) + `modinfo.json` + `build_package.py`.
- Графік: власний JSON-ендпоїнт модуля + Highcharts/CSV або pChart
  (`pChart/?p=Object.Property&op=log...`) для «типового chart» MajorDoMo.

## 3. Факти про API ТК (з [[perplexity_research|Дослідження API]] і перевірених SDK)

- Базовий URL: `https://www.tablycjakalorijnosti.com.ua` (UA) або
  `https://www.kaloricketabulky.cz` (CZ) — має бути **налаштуванням**.
- Логін: `POST /login/create?format=json&voucher=false`, тіло
  `{"email":"...","password":"<md5 utf8>"}`; помилка — у JSON `code != 0` навіть при HTTP 200.
  Сесійні cookies повертаються в `Set-Cookie` (UA: будь-які пари; CZ: `JSESSIONID`,
  UA SDK згадує `kaloricketabulky_token`) — зберігати **всі** пари й надсилати назад у `Cookie`.
- Щоденник: `GET /user/diary/ДД.ММ.РРРР/get?format=json` →
  `{code:0, data:{times:[6 слотів], carbohydrateTotal, sugarTotal, fiberTotal,
  proteinTotal, fatTotal, energyTotal, foodstuffCount, ...}}`.
- Слоти (`times[]`): `id` (`"1"`..`"6"`), `title`, `foodstuff[]`, `notes`, `energyTotal`.
  1 Сніданок, 2 Перекус, 3 Обід, 4 Підвечірок, 5 Вечеря, 6 Друга вечеря.
- Продукт у прийомі (`foodstuff[]`): `title`, `unit` (напр. `"166 x 1 g"`),
  `energy`/`energyUnit`, `protein`, `carbohydrate`, `fat`, `fiber`, `sugar`, `salt`,
  `saturatedFattyAcid` тощо, `guidType`, `url`, `id`.
- **Глікемічного індексу (GI) у відповіді немає**; нотатки є лише на рівні слота
  (`times[].notes`), не на рівні страви → GI і нотатки зберігаємо локально.
- Корисні додаткові ендпоїнти: `/user/diary/summary/.../get`, `/statistic/summary/.../get`,
  `/autocomplete/foodstuff-activity-meal?query=`, `/user/foodstuff/add/form/{id}`.
- **Запис у ТК існує, але неофіційний**: `POST /user/foodstuff/add?format=json` з
  `{guid,title,url,date,multiplier,diaryTimeGuid,unitGuid:"0000000000000001",unitOptions:[...]}`;
  видалення — `GET /user/diary/foodstuff/delete/{id}`. Використовувані бібліотеки явно
  позначають доступ як **read-only** і застерігають: «don't hammer the site… keep polling
  slow and infrequent». Будь-який запис — тільки за явним погодженням і вимкнений за замовчуванням.

## 4. Вимоги до реалізації

### 4.1 Налаштування (admin UI)
- Тип/адреса API (UA/CZ/власний base URL), email, пароль (маскування, без секретів у логах/репо).
- Період оновлення (хвилини/години, мінімальна межа напр. 15 хв), увімкнення/вимкнення циклу.
- Хук: вибір об'єкта і властивості MajorDoMo; зміна значення → примусове оновлення
  (з дебаунсом і захистом від петель).
- Термін зберігання даних, дефолт **5 років** (щоденне очищення прострочених рядків).
- Мова інтерфейсу (uk/en/ru), кількість грамів на 1 ХО (10 або 12), добові норми
  `CARBS_TARGET=120`, `CALORIES_TARGET=1800`, `PROTEIN_TARGET=90`, `FAT_TARGET=60`
  і `MEAL_NORM_SHARE=25` (діапазон 10–50, %) — частка основного прийому їжі від
  добової норми; решта норми ділиться порівну між перекусами (2, 4, 6).
- Кнопка «Перевірити підключення» (діагностика без зміни даних).

### 4.2 Синхронізація
- Фоновий цикл `scripts/cycle_tabcalorie.php` з інтервалом із налаштувань + ручний запуск.
- Інкрементальна синхронізація: останні N днів (напр. 2) + backfill за діапазоном.
- Ідемпотентність: унікальний ключ `(дата, слот, guid страви, unit)`; повторне оновлення
  не створює дублікатів (або `INSERT ... ON DUPLICATE KEY UPDATE`).
- **Захист від блокування**: один запит за раз, паузи ~300–500 мс між днями,
  exponential backoff, `single-flight` блокування (не запускати паралельні цикли),
  кешування, таймаути, circuit breaker після серії помилок, коректний `User-Agent`,
  жодного запису назад у ТК без явного прапорця, локальний режим «demo/fixtures» для тестів.

### 4.3 Зберігання даних (власні таблиці)
- `tabcalorie_entries`: дата/час, слот, назва страви, кількість×одиниця (`unit_raw`,
  `quantity`, `unit`), білки/жири/вуглеводи/клітковина/цукри/калорії, GI ( локально ),
  нотатки, `source` (tk/manual), `synced_at`, унікальний ключ.
- `tabcalorie_foods`: довідник унікальних страв із властивостями **на 100 г**
  (БЖУ без деталізації цукрів/кислот, клітковина, GI якщо відомий, нотатки, калорійність).
- `tabcalorie_days`: добові підсумки (вуглеводи, ХО, калорії, БЖУ, клітковина) для швидкого Огляду.
- `tabcalorie_sync_log`: час, тип, результат, HTTP-код, кількість рядків — без секретів.

### 4.4 Інтерфейс і Object
- Адаптивна верстка (CSS media queries, мобільний/десктоп), вкладки: **Огляд** (за
  замовчуванням, якщо плагін налаштовано), Історія, Довідник страв, Налаштування,
  Діагностика, Експорт, Інструкції.
- Огляд: дані за **останню заповнену добу** (не перестрибувати через добу: якщо
  сьогодні заповнено лише сніданок — обід має бути порожнім, а не з іншого дня).
- Якщо норми заповнені (не 0), у вкладці **Огляд** для кожного з 6 прийомів їжі
  показується прогресбар по вуглеводах, калоріях, білках і жирах відносно
  розрахованої норми прийому; перевищення виділяється кольором.
- Об'єкт MajorDoMo `TabCalorie.Day` із детальними властивостями-агрегатами за прийомами
  їжі (сніданок/перекус/обід/підвечірок/вечеря/друга вечеря) останньої заповненої доби +
  добові суми, дата, прапорець «частково заповнено», GI/вуглеводи.
- Кнопка «Створити типовий chart» — генерація графіка споживання (сніданок, обід,
  вечеря, підсумок за добу) через стандартний механізм MajorDoMo/pChart.
- Експорт CSV за період: день / тиждень / місяць / рік; BOM для Excel, розділювач
  налаштовується, локальні формати чисел/дат, без секретів у файлі.
- Діагностика: перевірка DNS/TLS/HTTP, логін, cookie, наявність ендпоїнта, парсинг JSON,
  останній успішний sync, пояснення типових помилок (інструкції для «Забули пароль»).
- Іконка плагіна — стилізована під іконку ТК (оригінальна, без копіювання чужого бренду
  без дозволу): SVG/PNG, `img/modules/tabcalorie.png`.

### 4.5 Безпека (публічний репозиторій)
- Жодних реальних логінів/паролів/токенів/персональних даних у репо, тестах, логах, знімках.
- Пароль у конфігурації — маскований у UI; у логах лише `***`.
- Усі SQL — через `DBSafe`/плейсхедери; екранування HTML у шаблонах; CSRF-перевірка
  адмін-дій; перевірка прав `control_access`.
- HTTPS only, валідація TLS, таймаути, обмеження розміру відповіді.
- Контроль доступу до експорту (персональні дані користувача), можливість анонімізації.
- Запис у ТК — **вимкнений за замовчуванням**, окремий прапорець і підтвердження.

### 4.7 Вимоги v1.2.0

- Службові поля страви у `tabcalorie_foods`: `FOOD_ID`, `FOOD_URL`, `UNIT_GUID`
  (`0000000000000001`), `UNIT_OPTIONS` (JSON), `DEFAULT_MULTIPLIER`,
  `DEFAULT_SLOT` (1..6), `SERVICE_JSON`; форма додавання/редагування страви у
  вкладці «Довідник страв» і пошук через autocomplete ТК. Write-back бере дані
  звідти, а не з жорстко заданих констант.
- Активність: `ACTIVITY_ENABLED=1`; `data.activities` → `tabcalorie_activities`
  (унікальний ключ — дата + ID активності) і `STEPS`, `ACTIVITY_KCAL`,
  `ACTIVITY_COUNT` у `tabcalorie_days`; вкладка «Активність» (добовий зріз +
  7-денний огляд) і колонки CSV. Health Connect у ТК односторонній — лише читання.
- Властивості `TabCalorie`: `status`, `raw`, `ActivitySteps`, `ActivityKcal`,
  `ActivityCount` (див. [[API|API та формати даних]]).
- Обслуговування БД: `LOG_RETENTION_DAYS=30`, `LOG_MAX_ROWS=2000`,
  `WRITE_QUEUE_TTL_DAYS=7`.

## 5. Корисні можливості понад запит (пропозиції)

1. Цільові межі вуглеводів за добу/прийом із сповіщеннями (для користувача) + «залишок ліміту».
2. ХО (bread units) із налаштовуваним співвідношенням 10/12 г на 1 ХО.
3. Порівняння з попередніми днями/тижнями, тренд і відхилення від цілі.
4. Режим `demo` з фікстурами — розробка й тести без реальних даних/облікового запису.
5. Ручні локальні записи з `source=manual` (не синхронізуються назад у ТК).
6. Історія синхронізацій + «останній успіх» і рядковий звіт (анонімізований CSV).
7. Імпорт/бекфіл за діапазоном дат із захистом від дублів і прогресом.
8. Замок ручних правок: не перезаписувати рядок, якщо користувач його редагував.
9. Вебхук/сповіщення MajorDoMo при перевищенні ліміту або при помилці синхронізації.
10. Експорт «звіт»: добові суми + ХО + інсулін (якщо додається вручну) в одному CSV.

## 6. Критерії прийняття

- `php -l` для всіх PHP-файлів; відсутність секретів у репо (перевірка `grep`).
- Встановлення пакета через Market і вручну (`tar -xzf ... -C /var/www/html/`).
- Синхронізація ідемпотентна; повторний запуск не дублює рядки.
- Огляд показує останню **заповнену** добу; порожні слоти не підтягуються з інших діб.
- Прогресбари норм відображаються для всіх 6 прийомів; перевищення виділяється кольором.
- CSV містить BOM і коректні суми за вибраний період.
- chart створюється через стандартний механізм MajorDoMo.
- Інструкції en/uk/ru повні й не містять реальних персональних даних.
- Усі зміни запушено в `mambursoft/majordomo_TabCalorie`.

## 7. Зафіксовані рішення (2026-11-20)

| Питання | Рішення |
|---|---|
| Запис назад у ТК | **З підтвердженням**: `WRITEBACK_ENABLED=0` за замовчуванням, кожен запис із черги відправляється лише після явного підтвердження. Read-only у звичайному режимі. |
| Домен ТК | **UA + CZ перемикач**: `PROVIDER=ua\|cz\|custom`, власний URL — тільки HTTPS. Дефолт `tablycjakalorijnosti.com.ua`. |
| Пароль і доступ | Конфіг модуля (`project_modules.DATA`), маскування в UI, `***` у логах, доступ через права адмінки MajorDoMo. |
| Слоти | **6 слотів + 3 групи**: `Slot1..Slot6Carbs/Kcal`, `GroupMainCarbs` (1+3+5), `GroupSnacksCarbs` (2+4+6), `GroupDayCarbs`. |
| GI та нотатки | Локальний редагований довідник `tabcalorie_foods.GI/NOTES` + нотатки рівня прийому їжі з API; `GI=0` якщо не заповнено. |
| CSV | UTF-8 **BOM**, розділювач **`;`**, дати `ДД.ММ.РРРР`, два види: добові підсумки та деталізація. Екранування formula-injection. |
| Nightscout | **Базовий push у v1**: один `Meal Bolus` на непорожній слот останньої заповненої доби, дедуплікація, вимкнено за замовчуванням. |
| Добові норми | `CALORIES_TARGET=1800`, `PROTEIN_TARGET=90`, `FAT_TARGET=60`, `CARBS_TARGET=120`, `MEAL_NORM_SHARE=25` (10–50%) — прогресбари в Огляді по 6 прийомах. |
