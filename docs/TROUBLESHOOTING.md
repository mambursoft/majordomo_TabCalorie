# Усунення несправностей TabCalorie

[[TROUBLESHOOTING|Українська]] · [[TROUBLESHOOTING.en|English]] · [[TROUBLESHOOTING.ru|Русский]]

Версія 1.3.0 · 2026-11-20

Цей документ допомагає діагностувати типові проблеми. Почніть із вкладки
**Діагностика** та кнопки **«Перевірити підключення»** — вона перевіряє
DNS/TLS/HTTP, логін, cookies, ендпоїнт і парсинг JSON, не змінюючи дані.

> [!WARNING]
> Ніколи не надсилайте у публічні issue реальні логи з паролями, токенами чи
> персональними даними користувача. Секрети в логах маскуються як `***` — перевірте це
> перед публікацією.

## Швидкий чеклист

- [ ] Модуль активний? Адмінка → **Модулі** → `tabcalorie`.
- [ ] Заповнені `EMAIL` і `PASSWORD`?
- [ ] `PROVIDER` відповідає порталу (`ua` / `cz` / `custom`)?
- [ ] `SYNC_ENABLED=1`?
- [ ] Сервер має вихідний HTTPS-доступ до порталу ТК?
- [ ] Розширення PHP `curl`, `json`, `mbstring` увімкнені?
- [ ] Що кажуть `LAST_ERROR`, `CIRCUIT_UNTIL` і `tabcalorie_sync_log`?

## 1. Помилки входу (логін)

### «Помилка входу: code != 0»

API ТК повертає помилку у JSON **`code != 0` навіть при HTTP 200** — перевіряйте
`тіло відповіді`, а не лише код стану.

Причини:

- неправильний email або пароль;
- обліковий запис створено через Google/Apple і не має прямого пароля;
- пароль передано у відкритому вигляді замість `md5(utf8)`.

**Рішення:**

1. Відкрийте `https://www.tablycjakalorijnosti.com.ua/login`.
2. Введіть email і натисніть **«Забули пароль?»**.
3. Отримайте лист із паролем для прямого входу (робота додатка на телефоні
   не перерветься).
4. Введіть новий пароль у налаштуваннях модуля і знову натисніть «Перевірити підключення».

### «Сервер не повернув сесійні cookies»

- Перевірте, що `BASE_URL` вказує на коректний портал і що відповідь містить
  `Set-Cookie`.
- Плагін зберігає **всі** пари cookie (UA: будь-які, CZ: `JSESSIONID`;
  UA SDK згадує `kaloricketabulky_token`) і надсилає їх назад у `Cookie`.
- Можливо, портал змінив схему авторизації — перевірте оновлення плагіна.

## 2. Помилки читання щоденника

### HTTP 403 / 401 при `GET /user/diary/…`

- Сесія застаріла — повторіть логін (див. вище).
- Cookie не передаються — перевірте конфіг і проксі-сервери.
- Можливо, спрацював захист сайту від частих запитів (див. розділ 4).

### «Помилка API для дати …» / порожній JSON

- Перевірте формат дати у шляху: **`ДД.ММ.РРРР`**, наприклад `20.11.2026`.
- Перевірте, що `code == 0` і присутній `data`.
- Для майбутніх або дуже давніх даних даних може не бути — це нормально.

### Огляд показує порожні слоти / дані не з'являються

- Плагін показує **останню заповнену добу**. Якщо сьогодні заповнено лише
  сніданок — обід буде порожнім, а не з іншого дня.
- Переконайтеся, що в ТК дійсно є записи за цю дату.
- Перевірте `SYNC_DAYS` — можливо, потрібно збільшити глибину або зробити бекфілл.
- Перевірте таблицю `tabcalorie_entries` на наявність рядків.

## 3. Помилки встановлення та конфігурації

### Модуль не видно після розпакування

- Розпакуйте архів у **корінь** MajorDoMo, а не в підпапку.
- Перевірте наявність `modules/tabcalorie/tabcalorie.class.php`.
- Оновіть кеш модулів в адмінці та перевірте права доступу до файлів
  (читання для вебсервера).

### Таблиці не створені

- Активуйте модуль через адмінку — `dbInstall()` виконується при встановленні.
- Перевірте права користувача БД на `CREATE TABLE`.
- Порівняйте з дзеркалом `modules/tabcalorie/db_install.php`
  (heredoc-формат `table: FIELD type...`).

### Пароль не зберігається / скидається

- Конфіг зберігається в `project_modules.DATA` через `getConfig()/saveConfig()`.
- Перевірте права на запис до БД і що ви редагуєте конфіг саме модуля
  `tabcalorie`.

## 4. Блокування, таймаути, circuit breaker

### «Занадто багато запитів» / тимчасове блокування з боку ТК

Сайт ТК не любить частого опитування. Плагін уже реалізує захист, але
перевірте налаштування:

- `SYNC_INTERVAL_MIN` **≥ 15** (рекомендовано 60);
- не запускайте фоновий цикл і ручний запуск одночасно (single-flight);
- не додавайте власні паралельні cron-задачі;
- паузи ~300–500 мс між записами вже вбудовані.

### `CIRCUIT_UNTIL` у майбутньому

Це означає, що після серії помилок плагін тимчасово припинив запити.

**Рішення:** усуньте причину помилок (див. вище), дочекайтеся закінчення паузи
або скиньте значення `CIRCUIT_UNTIL` в адмінці. Перевірте `LAST_ERROR`.

### Повільна синхронізація

- Зменшіть `SYNC_DAYS` (наприклад, 2).
- Перевірте швидкість і стабільність з'єднання сервера з порталом.
- Перевірте таймаути cURL — занадто великі значення подовжують очікування.

## 5. Експорт і дані

### CSV відкривається «кривими» літерами в Excel

- Файл має **BOM UTF-8** — перевірте, що його не зрізав поштовий клієнт.
- Розділювач — `;` (`CSV_DELIMITER`). У локальних налаштуваннях Excel UA
  саме `;` є стандартним. Якщо у вас інший локаль — змініть ключ.
- Дати у форматі `ДД.ММ.РРРР`.

### У CSV порожні суми

- Перевірте вибраний період (день/тиждень/місяць/рік).
- Перевірте наявність даних у `tabcalorie_days`.
- Для деталей страв перевірте `tabcalorie_entries`.

### Дані зникли через рік

`RETENTION_DAYS=1825` (5 років) — рядки старші за цей термін видаляються
щодня. Збільште значення, якщо потрібно довше зберігати історію.

## 6. GI, нотатки та запис назад у ТК

### GI або нотатки порожні

Це очікувано: **API ТК не віддає GI і нотаток страви**. Заповнюйте їх у вкладці
**Довідник** (таблиця `tabcalorie_foods`) — вони зберігаються локально і не
перезаписуються синхронізацією.

### Запис у ТК не працює

- Запис — **неофіційний** і вимкнений за замовчуванням (`WRITEBACK_ENABLED=0`).
- Увімкніть `WRITEBACK_ENABLED=1` і підтвердьте `WRITEBACK_CONFIRM=1`.
- Перевірте чергу `tabcalorie_write_queue` на наявність і стан записів.
- Пам'ятайте: бібліотеки позначають такий доступ як read-only і радять не
  «бомбардувати» сайт. Використовуйте обережно.

## 7. Nightscout

### Push у Nightscout не надходить

- Перевірте `NS_ENABLED=1`.
- Перевірте `NS_URL` (база без завершального слешу), наприклад `https://ns.example.org`.
- У заголовку `API-SECRET` передається **`sha1`** від `NS_API_SECRET`, а не
  сам секрет. Перевірте, що ви не ввели вже похешоване значення.
- Перевірте ендпоїнт `/api/v1/treatments.json` і доступність сервера.

## 8. Як повідомити про проблему

Створіть issue у https://github.com/mambursoft/majordomo_TabCalorie/issues і
додайте:

- версію плагіна (1.1.0), PHP і MajorDoMo;
- `PROVIDER` (без секретів!) і BASE_URL (без облікових даних);
- текст `LAST_ERROR` (перевірте, що там немає пароля);
- останні рядки `tabcalorie_sync_log` без персональних даних;
- кроки відтворення.

**Не додавайте:** реальні email/паролі, `NS_API_SECRET`, персональні дані користувача, cookies.
