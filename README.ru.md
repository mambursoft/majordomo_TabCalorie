> [!WARNING]
> **TabCalorie НЕ является медицинским прибором и не даёт медицинских рекомендаций.**
> Плагин не диагностирует, не назначает лечение, не рассчитывает и не вводит

> Все данные предназначены **исключительно для информационного контроля**
> потребления углеводов и формирования отчётности. Решения о дозах инсулина,
> питании и лечении принимает **врач**.
>
> Персональные данные пользователя и данные питания хранятся **локально** в вашей
> установке MajorDoMo. Не публикуйте реальные данные в публичных репозиториях,
> скриншотах и неанонимизированных отчётах.

## Назначение

TabCalorie автоматически забирает дневник питания из облачного портала
«Таблицы калорийности» в локальную базу MajorDoMo и показывает удобный срез
потребления углеводов по 6 приёмам пищи:

1. Завтрак
2. Перекус (второй завтрак)
3. Обед
4. Полдник
5. Ужин
6. Второй ужин

Мобильное приложение ТК передаёт данные только в свой облачный портал;
стандартные интеграции (Health Connect, Google Fit, Garmin, Samsung Health)
**не экспортируют** съеденные углеводы. Внутренний JSON API веб-портала
отдаёт полную структуру дня, и TabCalorie использует его для импорта
(подробнее — в [[perplexity_research|Исследовании API]]).

### Возможности

- Инкрементальная синхронизация последних N дней + бэкфилл за диапазон дат.
- Идемпотентность: уникальный ключ `(дата, слот, guid блюда, unit)` — повторные
  запуски не создают дублей.
- Обзор **последнего заполненного дня** с пустыми слотами, а не с данными из другого дня.
- Локальный справочник блюд со значениями на 100 г и локальные GI/заметки
  (в API ТК их нет). Служебные поля блюда (`FOOD_ID`, `FOOD_URL`, `UNIT_GUID`,
  `UNIT_OPTIONS`, `DEFAULT_MULTIPLIER`, `DEFAULT_SLOT`, `SERVICE_JSON`)
  используются для записи в ТК вместо жёстко заданных значений; во вкладке
  «Справочник блюд» есть форма добавления/редактирования блюда и поиск через
  autocomplete ТК.
- Активность из поля `data.activities` дневника ТК (данные Health Connect):
  шаги, сожжённые ккал, новая вкладка **Активность** и столбцы в CSV
  (`ACTIVITY_ENABLED`). Health Connect в ТК односторонний — плагин только
  считывает данные оттуда.
- Суточные нормы (калории, белки, жиры, углеводы) и прогрессбары по каждому из 6
  приёмов пищи на вкладке **Обзор**; превышение выделяется цветом.
- Объект MajorDoMo `TabCalorie` (класс `STabCalorie`) с готовыми агрегатами,
  включая `status`, `raw`, `ActivitySteps`, `ActivityKcal`, `ActivityCount`.
- Ротация `tabcalorie_sync_log` (`LOG_RETENTION_DAYS`, `LOG_MAX_ROWS`) и TTL
  очереди записи (`WRITE_QUEUE_TTL_DAYS`).
- Экспорт CSV (BOM UTF-8, разделитель `;`) за день / неделю / месяц / год.
- Диагностика подключения без изменения данных.
- Опциональный базовый push в Nightscout `/api/v1/treatments.json`.
- Запись обратно в ТК — **неофициальная**, по умолчанию отключена и только с подтверждением.
- Защита от блокировки: интервал ≥15 мин, паузы, backoff, single-flight,
  таймауты, circuit breaker, без параллельных запросов.
- Интерфейс на украинском, английском и русском (uk — по умолчанию).

## Требования

- MajorDoMo с модульным механизмом (`modules/`, `templates/`, `languages/`,
  `scripts/`, `img/modules/`).
- PHP **7.3–8.2** (проверено; минимальная версия 7.3), расширения `curl`, `json`,
  `mbstring`, доступ к собственной БД (MySQL/MariaDB) через MajorDoMo.
- Включённый HTTPS и валидная проверка TLS на сервере.
- Учётная запись «Таблицы калорийности» с паролем для прямого входа на сайт
  (см. FAQ, если вход через Google/Apple).

## Установка

### Вариант A — через Market MajorDoMo

1. В админке MajorDoMo откройте **Market / Каталог модулей**.
2. Найдите `TabCalorie` и нажмите **Установить**.
3. Подтвердите создание таблиц и регистрацию модуля.
4. Перейдите к настройкам модуля (ниже).

### Вариант B — вручную из архива `.tgz`

Пакет имеет структуру относительно корня MajorDoMo. Распакуйте в корень сайта:

```bash
cd /var/www/html
tar -xzf tabcalorie.tgz
```

После распаковки проверьте наличие файлов:

```text
modules/tabcalorie/tabcalorie.class.php
templates/tabcalorie/*.html
languages/tabcalorie_*.php
scripts/cycle_tabcalorie.php
img/modules/tabcalorie.png
modinfo.json
```

Далее в админке → **Модули** → список активных → **`tabcalorie` → Установить**.
Модуль сам создаст таблицы, зарегистрирует флаг
`cms/modules_installed/tabcalorie.installed`, строку в таблице `plugins`,
объект `TabCalorie` и иконку.

> [!NOTE]
> Сборка пакета выполняется командой `python3 build_package.py` — результат
> `dist/tabcalorie.tgz`. Подробнее: [[INSTALL.ru|Инструкция по установке]].

## Настройки

Конфигурация хранится в `project_modules.DATA` (сериализованный массив) и
редактируется в админке модуля. Пароли и секреты маскируются в UI и никогда не
попадают в логи или репозиторий.

| Ключ | Тип / значение | По умолчанию | Назначение |
|---|---|---|---|
| `BASE_URL` | URL | `https://www.tablycjakalorijnosti.com.ua` | Базовый URL портала ТК. Для CZ — `https://www.kaloricketabulky.cz`. |
| `PROVIDER` | `ua` \| `cz` \| `custom` | `ua` | Провайдер. `custom` использует `BASE_URL`. |
| `EMAIL` | строка | — | Email учётной записи ТК. |
| `PASSWORD` | строка (маскируется) | — | Пароль прямого входа; передаётся как `md5`. |
| `SYNC_ENABLED` | 0/1 | `1` | Включение фонового цикла. |
| `SYNC_INTERVAL_MIN` | минуты | `60` | Интервал синхронизации (минимум **15 мин**). |
| `SYNC_DAYS` | дни | `2` | Сколько последних дней обновлять за запуск. |
| `HOOK_ENABLED` | 0/1 | `0` | Принудительное обновление при изменении свойства MajorDoMo. |
| `HOOK_PROPERTY` | `Obj.Prop` | — | Свойство-триггер для хука. |
| `HOOK_DEBOUNCE_SEC` | секунды | `60` | Дебаунс, чтобы избежать петель и лишних вызовов. |
| `RETENTION_DAYS` | дни | `1825` (5 лет) | Срок хранения данных; просроченные строки удаляются ежедневно. |
| `ACTIVITY_ENABLED` | 0/1 | `1` | Импорт активности из `data.activities` дневника ТК (данные Health Connect в ТК), включён по умолчанию. |
| `LOG_RETENTION_DAYS` | дни | `30` | Ротация `tabcalorie_sync_log`: удаление строк старше N дней. |
| `LOG_MAX_ROWS` | строки | `2000` | Ротация `tabcalorie_sync_log`: ограничение количества строк (удаляются самые старые). |
| `WRITE_QUEUE_TTL_DAYS` | дни | `7` | Очистка `tabcalorie_write_queue`: удаление просроченных строк при cleanup. |
| `LANGUAGE` | `uk` \| `en` \| `ru` | `uk` | Язык интерфейса. |
| `GRAMS_PER_XE` | число | `10` | Граммов углеводов на 1 ХЕ (10 или 12 — по назначению врача). |
| `CALORIES_TARGET` | ккал | `1800` | Суточная норма калорий, ккал. |
| `PROTEIN_TARGET` | граммы | `90` | Суточная норма белков, г. |
| `FAT_TARGET` | граммы | `60` | Суточная норма жиров, г. |
| `CARBS_TARGET` | граммы | `120` | Суточная норма углеводов, г. |
| `MEAL_NORM_SHARE` | процент (10–33) | `25` | Доля основного приёма пищи (завтрак/обед/ужин) от суточной нормы; остаток нормы делится поровну между перекусами (2, 4, 6). |
| `CSV_DELIMITER` | символ | `;` | Разделитель CSV (совместим с Excel UA). |
| `WRITEBACK_ENABLED` | 0/1 | `0` | Неофициальная запись обратно в ТК — **отключена**. |
| `WRITEBACK_CONFIRM` | 0/1 | `1` | Требовать явное подтверждение каждой записи. |
| `NS_ENABLED` | 0/1 | `0` | Push в Nightscout — **отключён**. |
| `NS_URL` | URL | — | База вашего Nightscout (напр. `https://ns.example.org`). |
| `NS_API_SECRET` | строка (маскируется) | — | API_SECRET; передаётся как `sha1` в заголовке. |
| `LAST_SYNC` | timestamp | — | Время последней успешной синхронизации (служебное поле). |
| `LAST_ERROR` | строка | — | Последняя ошибка (без секретов). |
| `CIRCUIT_UNTIL` | timestamp | — | Пауза circuit breaker после серии ошибок. |

> [!TIP]
> Норма основного приёма пищи (завтрак, обед, ужин) рассчитывается как
> `суточная норма × MEAL_NORM_SHARE / 100`. Остаток суточной нормы
> `(100 − MEAL_NORM_SHARE)%` делится поровну между тремя перекусами (слоты 2, 4, 6).
> Например, при `MEAL_NORM_SHARE=25` основные приёмы получают по 25% нормы,
> а перекусы — по ~8,33% каждый.

После сохранения нажмите **«Проверить подключение»** — это диагностика без
изменения данных: DNS/TLS/HTTP, логин, cookie, наличие эндпоинта, парсинг JSON.

## Использование

Публичная страница плагина (`run()` + `templates/tabcalorie/tabcalorie.html`)
содержит семь вкладок:

| Вкладка | Что делает |
|---|---|
| **Обзор** | Данные за последний заполненный день: 6 слотов, группы приёмов, суточные суммы, ХЕ, % от цели, остаток лимита, прогрессбары по нормам. Вкладка по умолчанию, если плагин настроен. |
| **Активность** | Шаги и сожжённые калории за последний заполненный день и 7-дневный обзор; данные из `data.activities` дневника ТК (Health Connect, только чтение). |
| **История** | Суточные суммы за период, сравнение с предыдущими днями, тренд и отклонение от цели. |
| **Справочник блюд** | Локальный справочник блюд со значениями на 100 г; GI и заметки; форма добавления/редактирования блюда со служебными полями и поиск через autocomplete ТК. |
| **Экспорт** | CSV за день / неделю / месяц / год, BOM UTF-8, разделитель `;`, формат дат `ДД.ММ.ГГГГ`; теперь с шагами и сожжёнными ккал; возможна анонимизация. |
| **Диагностика** | Состояние последней синхронизации, лог синхронизаций, пояснения типовых ошибок, результат «Проверить подключение». |
| **Инструкции** | Краткие инструкции uk/en/ru (включая «Забыли пароль?»). |

> [!IMPORTANT]
> Если нормы заполнены (не 0), на вкладке **Обзор** для каждого из 6 приёмов пищи
> отображается прогрессбар по углеводам, калориям, белкам и жирам относительно
> рассчитанной нормы приёма; превышение выделяется цветом.

На вкладке **Обзор** доступна кнопка **«Создать типовой chart»** — генерация
графика потребления через стандартный механизм MajorDoMo (Highcharts/pChart).

### Вкладка «Активность»

При `ACTIVITY_ENABLED=1` (по умолчанию) плагин считывает записи активности из
поля `data.activities` дневника ТК (`steps`, `energy`, `title`, `type`,
`activityType`, длительность). Каждая активность сохраняется в таблице
`tabcalorie_activities` с уникальным ключом **дата + ID активности**, а суточные
суммы `STEPS`, `ACTIVITY_KCAL`, `ACTIVITY_COUNT` — в `tabcalorie_days`.

Вкладка показывает:

- [ ] суточный срез: шаги, сожжённые ккал и список активностей за последний заполненный день;
- [ ] 7-дневный обзор: шаги и ккал по дням;
- [ ] те же шаги и сожжённые ккал добавляются в CSV-экспорт.

> [!WARNING]
> Health Connect в ТК односторонний: активность попадает в дневник ТК, а плагин
> только считывает её оттуда. Плагин **ничего не пишет** в Health Connect.

### Форма блюда в справочнике

Во вкладке **Справочник блюд** доступны:

- [ ] форма добавления/редактирования блюда: название, ID, URL, единица, граммы, слот,
  БЖУ/ккал на 100 г, GI, заметки;
- [ ] поиск блюда через autocomplete ТК (`/autocomplete/foodstuff-activity-meal?query=`);
- [ ] служебные данные: `FOOD_ID` (guid для API), `FOOD_URL` (путь `potraviny/...`),
  `UNIT_GUID` (по умолчанию `0000000000000001`), `UNIT_OPTIONS` (JSON доступных
  единиц с множителями), `DEFAULT_MULTIPLIER` (граммы по умолчанию),
  `DEFAULT_SLOT` (1..6), `SERVICE_JSON` (сырой ответ формы ТК).

> [!TIP]
> Запись в ТК использует эти служебные данные блюда, а не жёстко заданные
> значения (`guid`, `url`, `unitGuid`, `unitOptions`, `multiplier`).

### Объект MajorDoMo `TabCalorie`

Класс `STabCalorie`. Читать свойства можно через `gg('TabCalorie.Свойство')`.

| Свойство | Описание |
|---|---|
| `LastDate` | Дата последнего заполненного дня. |
| `Partial` | Флаг частично заполненного дня. |
| `FilledSlots` | Сколько из 6 слотов заполнено. |
| `Slot1Carbs` … `Slot6Carbs` | Углеводы (г) по каждому из 6 приёмов. |
| `Slot1Kcal` … `Slot6Kcal` | Калории по каждому из 6 приёмов. |
| `GroupMainCarbs` | Сумма слотов 1+3+5 (основные приёмы). |
| `GroupSnacksCarbs` | Сумма слотов 2+4+6 (перекусы). |
| `GroupDayCarbs` | Суточная сумма углеводов. |
| `TotalCarbs`, `TotalKcal`, `TotalProtein`, `TotalFat`, `TotalFiber`, `TotalSugar`, `TotalXE`, `GI`, `Notes`, `Updated` | Суточные суммы, ХЕ, GI, заметки, время обновления. |
| `status` | `1`, если интеграция здорова; `0` при любой проблеме интеграции (`LAST_ERROR`, открытый circuit breaker) или если отключён фоновый цикл (`SYNC_ENABLED=0` либо `cycle_tabcalorieRun` старше ~10 мин). |
| `raw` | JSON со всеми данными от начала последних суток, по которым есть хотя бы одна запись: сырой дневник ТК + нормализованные записи. |
| `ActivitySteps`, `ActivityKcal`, `ActivityCount` | Агрегат активности (шаги, сожжённые ккал, количество активностей) за последний заполненный день. |

> [!NOTE]
> `status=0` означает любую проблему интеграции или остановленный фоновый цикл —
> проверьте `LAST_ERROR`, `CIRCUIT_UNTIL`, `SYNC_ENABLED` и время последнего
> запуска `cycle_tabcalorieRun` (не старше ~10 мин). `raw` предназначен для
> диагностики и содержит сырые данные ТК вместе с нормализованными записями.

### Обслуживание БД (v1.2.0)

- [ ] `tabcalorie_sync_log`: ротация по `LOG_RETENTION_DAYS` (30 дней) и
  `LOG_MAX_ROWS` (2000 строк); сначала удаляются самые старые строки.
- [ ] `tabcalorie_write_queue`: строки старше `WRITE_QUEUE_TTL_DAYS` (7 дней)
  удаляются автоматически при cleanup.

## Модель данных (собственные таблицы)

| Таблица | Назначение |
|---|---|
| `tabcalorie_entries` | Отдельные записи блюд: дата, слот, блюдо, количество × единица, БЖУ/клетчатка/сахара/калории, GI, заметки, `source` (`tk`/`manual`), `synced_at`. Уникальный ключ `date + slot + food_guid + unit_raw`. |
| `tabcalorie_foods` | Справочник уникальных блюд со значениями **на 100 г** и служебными полями `FOOD_ID`, `FOOD_URL`, `UNIT_GUID` (`0000000000000001`), `UNIT_OPTIONS`, `DEFAULT_MULTIPLIER`, `DEFAULT_SLOT` (1..6), `SERVICE_JSON`. |
| `tabcalorie_days` | Суточные суммы для быстрого Обзора, включая `STEPS`, `ACTIVITY_KCAL`, `ACTIVITY_COUNT`. |
| `tabcalorie_activities` | Активность из `data.activities` ТК; уникальный ключ — дата + ID активности. |
| `tabcalorie_sync_log` | Время, тип, результат, HTTP-код, количество строк — **без секретов**; ротация по `LOG_RETENTION_DAYS` / `LOG_MAX_ROWS`. |
| `tabcalorie_write_queue` | Очередь записей обратно в ТК с подтверждением (`WRITEBACK_*`); TTL `WRITE_QUEUE_TTL_DAYS`. |

## API ТК и ограничения

- Логин: `POST /login/create?format=json&voucher=false`, тело
  `{"email":"…","password":"<md5 utf8>"}`. Ошибка возвращается в JSON как
  `code != 0` **даже при HTTP 200**. Все пары `Set-Cookie` сохраняются и
  отправляются обратно в заголовке `Cookie`.
- Дневник: `GET /user/diary/ДД.ММ.ГГГГ/get?format=json` →
  `{code:0, data:{times:[6 слотов], carbohydrateTotal, sugarTotal, fiberTotal, proteinTotal, fatTotal, energyTotal, …}}`.
- Активность (v1.2.0): ТК возвращает `data.activities` (`steps`, `energy`, `title`,
  `type`, `activityType`, длительность) — данные включённой в ТК интеграции с
  Health Connect. При `ACTIVITY_ENABLED=1` они импортируются в
  `tabcalorie_activities`. Health Connect односторонний: плагин ничего не пишет в него.
- **GI и заметок блюда в API нет** — они ведутся локально в справочнике, где
  теперь сохраняются и служебные поля блюда для записи в ТК.
- Запись обратно в ТК — **неофициальная**: только при `WRITEBACK_ENABLED=1` и
  `WRITEBACK_CONFIRM=1`, через отдельную очередь. Библиотеки помечают такой
  доступ как read-only и советуют «не бомбардировать сайт».
- **Защита от блокировки:** интервал ≥15 мин, паузы ~300–500 мс между записями,
  exponential backoff, single-flight блокировка, таймауты, circuit breaker
  (`CIRCUIT_UNTIL`), корректный `User-Agent`, никаких параллельных запросов.

Подробнее: [[API|API и форматы данных]] (укр./en).

### Nightscout (опционально)

При `NS_ENABLED=1` плагин выполняет базовый push в `/api/v1/treatments.json`
вашего Nightscout. В заголовке `API-SECRET` передаётся `sha1` от вашего
`NS_API_SECRET`. По умолчанию отключено; для клинических отчётов используйте
штатные Nightscout Reports.

php -S 127.0.0.1:8765 tests/mock_server.php   # локальный mock ТК

Подробнее: [[tests/README|Тесты]]. Для первого запуска без учётной
записи включите `DEMO_MODE` — плагин работает на демонстрационных данных, не
делает сетевых запросов и не может писать в ТК или Nightscout.

## Безопасность

- Никаких реальных логинов/паролей/токенов/персональных данных в репозитории,
  тестах, логах и скриншотах.
- `PASSWORD` и `NS_API_SECRET` маскируются (`***`) в UI и логах.
- Все SQL — через `DBSafe`/плейсхолдеры; HTML экранируется в шаблонах; админ-действия
  защищены CSRF-проверкой и правами `control_access`.
- Только HTTPS, валидация TLS, таймауты, ограничение размера ответа.
- Контроль доступа к экспорту (персональные данные пользователя) и возможность анонимизации.
- Первый запуск в режиме demo/fixtures без реальной учётной записи.

Подробнее: [[SECURITY|Безопасность]] (укр./en).

## FAQ

**Нужен ли отдельный пароль, если я вхожу через Google/Apple?**
Да. Откройте `/login`, введите email и нажмите «Забыли пароль?» — на почту
придёт пароль для прямого входа. Работа приложения на телефоне не прервётся.

**Почему Обзор показывает пустой обед, хотя вчера он был заполнен?**
Потому что плагин показывает **последний заполненный день** и не подтягивает
слоты из других дней.

**Почему углеводы не берутся автоматически из Health Connect / Google Fit?**
Потому что эти интеграции ТК односторонние и не экспортируют КБЖУ. Начиная с v1.2.0
плагин считывает из ТК только активность (`data.activities`: шаги и сожжённые ккал,
`ACTIVITY_ENABLED`); углеводы по-прежнему импортируются этим плагином из дневника ТК.

**Сколько граммов на 1 ХЕ?**
По умолчанию 10. Если врач считает 12 — измените `GRAMS_PER_XE`.

**Можно ли полностью запретить запись в ТК?**
Да, по умолчанию: `WRITEBACK_ENABLED=0`. Даже включённая запись требует
подтверждения (`WRITEBACK_CONFIRM=1`).

**Где хранятся данные?**
Только локально, в вашей БД MajorDoMo. Облако ТК используется только для чтения дневника.

**Что означает `TabCalorie.status = 0`?**
Проблема интеграции или остановленный фоновый цикл: проверьте `LAST_ERROR`,
`CIRCUIT_UNTIL`, `SYNC_ENABLED` и время `cycle_tabcalorieRun` (не старше ~10 мин).
Свойство `raw` содержит сырые данные ТК и нормализованные записи для диагностики.

## Обновление и удаление

- **Обновление:** установите новый `.tgz` поверх текущего (сохраните конфиг),
  затем проверьте таблицы миграцией модуля.
- **Удаление:** в админке → **Модули** → деактивируйте `tabcalorie`. Таблицы с
  данными удаляются явным действием; конфиг в `project_modules.DATA` сохраняется
  до ручной очистки.
